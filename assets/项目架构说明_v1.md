## 一、项目定位

华夏航旅是面向温州华夏航服管理打造的 **B2B2C 综合航旅服务平台**，构建从 **平台运营方 → TMC 集团客户 → 商户/分销商 → 终端消费者** 的全链路航旅交易与管理体系。

业务覆盖：**机票 · 火车票 · 酒店 · 积分商城** 四大核心模块，对接 **航司直连 / 12306 / OTA 全渠道**。

## 二、整体架构总览

### 2.1 三端隔离架构（核心约定）

平台采用 **物理隔离的三后台架构**，三端代码独立、数据独立、用户体系独立、权限体系独立：

```
├──────────────────────┼──────────────────────┼───────────────────────┤

│                      │                      │                       │
│ 主要能力：              │ 主要能力：             │ 主要能力：               │
│ • 租户/套餐管理         │ • 集团差旅政策          │ • 商户内员工管理         │
│ • 全平台监控/统计       │ • 集团员工管理          │ • 商户订单管理           │
│ • 资源池/航司对接       │ • 集团报表             │ • 商户结算/对账          │
│ • 菜单/权限模板         │ • 子商户管控            │ • 终端用户运营           │
└──────────────────────┴──────────────────────┴───────────────────────┘
                                  ↓
                         前端: 小程序 / H5 / APP
                              (终端消费者购票/购酒店)
```

三端从用户、菜单、角色、岗位、部门、操作日志、登录日志 **全部物理分表**，便于：
- 独立扩容
- 独立权限模型迭代
- 独立部署灰度
- 安全隔离（拖库一张表不影响其他端）

### 2.2 双维度概念严格不混

| 维度 | 字段 | 取值 | 用途 |
|---|---|---|---|
| **后台标识 (Platform)** | `platform` / `*_user` 表前缀 | `pmc` / `tmc` / `mmc` | 决定路由到哪个后台、走哪套登录、查哪张 user 表 |

### 5.1 主体与域编码格式

| 端 | sub (主体) 格式 | dom (域) 格式 |
|---|---|---|

### 5.2 rules 表 v0~v5 语义

| 字段 | p 策略含义 | g 关系含义 |
|---|---|---|
| ptype | `p` 或 `g` | `g` |
| v0 | sub (主体编码) | 用户主体 |
| v1 | dom (域) | `role:{rid}` |
| v2 | obj (permission_key, e.g. `order:export`) | domain |
| v3 | act (操作) | - |

### 5.3 数据权限补充

Casbin 解决「能不能点这个菜单/按钮」，`data_permission_policy` 解决「能看见哪些数据」。

数据权限策略类型：

| policy_type | 含义 |
|---|---|
| `SELF` | 仅本人 |
| `DEPT_SELF` | 本部门 |
| `DEPT_TREE` | 本部门及下级 |
| `ALL` | 全部 |
| `CUSTOM_DEPT` | 自定义部门集合（值在 `value` JSON 字段） |
| `CUSTOM_FUNC` | 自定义函数（值在 `value` JSON 字段） |

## 六、安全与脱敏体系

### 6.1 手机号/邮箱三字段法

每张 `*_user` 表对 phone/email 都有 3 个字段：

| 字段 | 类型 | 存什么 | 用途 |
|---|---|---|---|
| `phone` | varchar(20) | **脱敏明文**: `138****8888` | 列表展示，不解密 |
| `phone_encrypted` | varbinary(255) | AES-256-GCM 密文 | 详情解密展示 |
| `phone_hash` | char(64) ascii_bin | HMAC-SHA256 十六进制 | 精确查找（登录、校验唯一）|

唯一约束切到 `phone_hash` 字段（脱敏明文不再唯一）。同理 email。

### 6.2 密钥管理

- `HX_ENCRYPT_KEY` — AES-256-GCM 32 字节，应用层 .env
- `HX_HASH_PEPPER` — HMAC-SHA256 ≥32 字节 pepper，应用层 .env
- **严禁入库 / 严禁进 git / 严禁打日志**
- key 轮换：双 key 在线轮换方案（v_old + v_new 并存）

### 6.3 三方 OAuth token 加密

`user_third_party_auth.access_token` / `refresh_token` 字段为 `VARBINARY(1024)`，应用层 AES-256-GCM 加密后入库。

### 6.4 账号安全

每张 `*_user` 表均含：
- `password_updated_at` — 强制密码定期更换
- `pwd_error_count` — 连续错误次数（达阈值锁定）
- `locked_until` — 锁定截止时间
- `enable_2fa` — 是否启用两步验证

## 七、租户层级与套餐归属

```
平台 (PMC, tenant_id=0)
 │
 ├─ TMC 集团客户 (tenant_type=tmc)                ←─ 用 tmc_package
 │   ├─ 商户 A (tenant_type=merchant, parent=TMC) ←─ 用 mmc_package
 │   ├─ 商户 B (tenant_type=merchant, parent=TMC)
 │   └─ 分销商 (tenant_type=distributor)
 │
 └─ 平台直建商户 (tenant_type=merchant, parent=0) ←─ 用 mmc_package
```

`tenant.user_id` 指向租户主管理员，**按 tenant_type 在对应 user 表查**：
- `tenant_type='tmc'` → `tmc_user.id`
- `tenant_type='merchant'/'distributor'` → `mmc_user.id`

`tenant.package_id` (tmc 套餐) 与 `tenant.mmc_package_id` (mmc 套餐) 按 tenant_type 互斥使用。
