# 审批流程对接第三方OA - 架构更新方案

## 一、设计变更概述

### 变更原因
审批流程自建完整的可视化流程设计器（原8张表）开发成本高、周期长，且企业用户已普遍使用钉钉/飞书/企业微信等OA系统。对接第三方OA可：
- **降低开发成本**：无需自建流程引擎和设计器前端
- **提升用户体验**：员工在熟悉的OA系统中完成审批，无需切换
- **增强合规性**：审批记录存档在第三方OA，具备法律效力
- **快速上线**：核心只需做对接适配层，而非完整流程引擎

### 变更范围
| 维度 | 变更前 | 变更后 |
|------|--------|--------|
| 流程设计器 | 自建8张表 + 可视化拖拽前端 | 移除，改用第三方OA原生流程 |
| 审批引擎 | 自建运行时（approval_instance/record） | 保留实例记录，审批流转由第三方OA执行 |
| 审批发起 | 平台内发起 | 平台内发起 → 推送到第三方OA |
| 审批操作 | 平台内操作 | 在第三方OA中操作 → 回调通知平台 |
| 审批回调 | 无 | 新增：接收第三方OA审批结果回调 |
| 审批查询 | 平台内查询 | 双向：平台可查 + OA可查 |

### 保留能力
- **审批单创建**：平台内根据业务场景（差旅审批三种模式）创建审批单
- **审批状态同步**：实时接收第三方OA回调，更新审批单状态
- **审批后业务联动**：审批通过后自动触发下单/退款等业务动作
- **审批记录查询**：平台内可查看审批历史，同时可跳转到OA查看详情

## 二、支持的第三方OA平台

| OA平台 | 对接方式 | 核心API | 状态 |
|--------|---------|---------|------|
| **钉钉** | 服务端API + 回调 | 创建审批实例 / 注册回调 / 获取审批详情 | 一期 |
| **飞书** | 服务端API + 事件订阅 | 创建审批实例 / 订阅审批事件 / 获取审批详情 | 一期 |
| **企业微信** | 服务端API + 回调 | 提交审批申请 / 接收审批状态变化通知 | 二期 |
| **泛微/致远等** | OpenAPI + Webhook | 视具体厂商API而定 | 三期(按需) |

## 三、架构设计

### 3.1 审批流程交互图

```
┌──────────────┐     ┌──────────────┐     ┌──────────────────────┐
│   C端/MMC端   │     │  华夏航服平台   │     │   第三方OA平台         │
│              │     │              │     │  (钉钉/飞书/企微)      │
│  提交审批单    │────>│  创建审批实例    │────>│  创建OA审批实例         │
│              │     │  保存审批记录    │     │  推送审批通知           │
│              │     │              │     │                      │
│              │     │              │     │  审批人操作           │
│              │     │              │     │  (同意/拒绝/转交/加签)  │
│              │     │              │     │         │             │
│              │     │              │     │         ▼             │
│  收到审批结果  │<────│  接收回调通知    │<────│  回调通知审批结果       │
│  (站内信/推送) │     │  更新审批状态    │     │                      │
│              │     │  触发业务联动    │     │                      │
└──────────────┘     └──────────────┘     └──────────────────────┘
```

### 3.2 审批三种模式的对接流程

#### 模式1: 先审后单（MMC端创建审批单→审批通过→下单）
```
MMC端用户创建审批单(选航线/乘机人)
    → 平台创建 approval_instance (status=pending)
    → 调用第三方OA API 创建审批实例
    → OA审批人收到通知
    → 审批通过 → 回调通知平台
    → 平台更新 approval_instance (status=approved)
    → MMC端用户基于审批单直接下单(航线/乘机人自动填充)
```

#### 模式2: 审批下单（C端选差旅审批→审批通过→自动下单）
```
C端用户搜索航班 → 选座 → 选择"差旅审批"支付方式
    → 平台创建 approval_instance (status=pending, mode=approval_order)
    → 锁座(临时占位，设超时时间)
    → 调用第三方OA API 创建审批实例
    → 审批通过 → 回调通知平台
    → 平台自动下单+出票
    → 审批拒绝 → 释放占座
```

#### 模式3: 先付后审（C端支付下单→期限内提交审批→审批通过→原路退款）
```
C端用户正常支付下单(已完成)
    → 订单列表中有"差旅审批"按钮(期限由MMC配置)
    → 用户点击提交审批
    → 平台创建 approval_instance (status=pending, mode=post_order)
    → 调用第三方OA API 创建审批实例
    → 审批通过 → 回调通知平台 → 原路退款
    → 审批拒绝 → 无操作(订单已生效)
```

### 3.3 业务联动事件

审批状态变更后触发的业务动作：

| 审批结果 | 模式1(先审后单) | 模式2(审批下单) | 模式3(先付后审) |
|---------|--------------|--------------|--------------|
| 通过 | 通知MMC用户下单 | 自动下单+出票 | 原路退款 |
| 拒绝 | 通知MMC用户 | 释放占座+通知C端 | 无操作 |
| 撤销 | 关闭审批单 | 释放占座 | 关闭审批单 |
| 超时 | 通知提交人 | 释放占座+通知 | 关闭审批单 |

## 五、对接适配层设计

### 5.1 适配器接口（Strategy模式）

```php
namespace App\Service\OA\Contract;

interface OaAdapterInterface
{
    /** 创建审批实例 */
    public function createApproval(array $params): OaApprovalResult;
    
    /** 获取审批详情 */
    public function getApprovalDetail(string $instanceId): OaApprovalDetail;
    
    /** 撤销审批 */
    public function cancelApproval(string $instanceId, string $reason): bool;
    
    /** 转交审批 */
    public function transferApproval(string $instanceId, string $toUserId): bool;
    
    /** 验证回调签名 */
    public function verifyCallback(array $headers, string $body): bool;
    
    /** 解析回调数据 */
    public function parseCallback(string $body): OaCallbackData;
    
    /** 获取用户信息(用于映射) */
    public function getUserInfo(string $userId): OaUserInfo;
    
    /** 获取部门列表(用于同步) */
    public function getDepartmentList(): array;
}
```

### 5.2 适配器实现

| 适配器 | 类名 | 对接文档 |
|--------|------|---------|
| 钉钉 | `App\Service\OA\DingTalkAdapter` | 钉钉开放平台-审批 |
| 飞书 | `App\Service\OA\FeishuAdapter` | 飞书开放平台-审批 |
| 企业微信 | `App\Service\OA\WeComAdapter` | 企微开放平台-审批 |

### 5.3 回调处理流程

```
第三方OA回调 → API网关 → OaCallbackController
    → 验签(verifyCallback)
    → 幂等校验(oa_callback_log.callback_id)
    → 解析回调数据(parseCallback)
    → 更新approval_instance状态
    → 写入approval_record
    → 触发业务联动事件(BusinessActionEvent)
        → 模式1: 通知MMC用户下单
        → 模式2: 自动下单+出票 / 释放占座
        → 模式3: 原路退款
    → 发送通知(站内信/微信模板消息)
    → 返回success给OA
```

## 七、安全设计

### 7.1 凭证安全
- AppSecret、CallbackToken、CallbackAesKey 使用AES-256加密存储
- 数据库中只存密文，运行时解密
- 密钥通过环境变量注入，不硬编码

### 7.2 回调安全
- 验签：所有回调必须通过签名验证
- 幂等：callback_id 唯一索引，防止重复处理
- IP白名单：可配置OA回调来源IP
- 超时重试：回调处理超时3次后标记为失败，人工介入

### 7.3 数据脱敏
- oa_callback_log.request_body 加密存储，7天后自动清理
- oa_callback_log.request_headers 脱敏后存储
- 审批意见中的敏感信息按需脱敏
