## 一、项目概述

| 维度 | 内容 |
|------|------|
| **项目名称** | 温州华夏航服管理系统 |

## 三、三端权限与数据隔离模型

### 3.1 三端映射关系

| 合同术语 | 数据库前缀 | 全称 | 层级 | 入口 |
|---------|-----------|------|------|------|
| 平台管理端 | `pmc_` | Platform Management Center | 最顶层 | Web后台 |
| 集团管理端 | `tmc_` | Team Management Center | PMC之下 | Web后台 |
| 商户端 | `mmc_` | Merchant Management Center | TMC之下 | Web后台 + 独立小程序 |

### 3.2 权限模型

```
三端共用 Casbin 权限验证逻辑，各自独立权限表:

PMC: pmc_user → pmc_role → pmc_menu → pmc_department
TMC: tmc_user → tmc_role → tmc_menu → tmc_department
MMC: mmc_user → mmc_role → mmc_menu → mmc_department

数据隔离: tenant_id 字段 (多租户)
Casbin策略: 各端独立 casbin_rule 表
```

### 3.3 租户隔离范围

| 隔离维度 | PMC可见 | TMC可见 | MMC可见 |
|---------|---------|---------|---------|
| TMC数据 | 全部 | 本集团 | 无 |
| MMC数据 | 全部(跨TMC) | 本集团下 | 本商户 |
| C端用户 | 全部 | 本集团下 | 本商户下 |
| 订单数据 | 全部 | 本集团下 | 本商户下 |
| 财务数据 | 全部 | 本集团 | 本商户 |
| 采购渠道 | 配置 | TMC可用列表 | TMC分配列表 |

## 四、核心业务链路

### 4.1 订单全链路（最复杂）

```
C端用户下单
  ↓ (归属MMC)
MMC接单
  ↓ (提交TMC)
TMC处理
  ↓ ┌──────────────┬──────────────┐
     │              │              │
  内采路径       外采路径       OpenAPI路径
  TMC→PMC       TMC直采       第三方→TMC→...
     │              │              │
  PMC对接        TMC人工         订单tag标识
  上游渠道       B2B出票         来源区分
     │              │              │
  自动/手动      导入核销        自动采购
  出票             │              │
     └──────────────┴──────────────┘
                    ↓
              出票成功/失败
                    ↓
         ┌──── 成功 ────┐──── 失败 ────┐
         ↓              ↓              ↓
    订单完成        人工介入        退改处理
    通知C端         联系客户
```

### 4.2 结算全链路

```
C端 → MMC: 实时支付(微信/支付宝) → payment_log
MMC → TMC: 预付/月结/信用额度 → finance_company_account
TMC → 供应商: 预付/月结/信用额度 → finance_supplier_account

内采: TMC → PMC → 供应商 (TMC付给PMC)
外采: TMC → 供应商直接 (TMC直付)
```

### 4.3 审批全链路（对接第三方OA）

```
触发场景1: MMC端创建审批单 → OA发起 → 审批通过 → MMC端下单
触发场景2: C端选差旅审批 → OA发起 → 审批通过 → 自动下单
触发场景3: C端先支付 → 7日内提交审批 → 审批通过 → 原路退款

OA对接: 钉钉/飞书/企业微信
同步方式: approval_instance.third_party_status 轮询 + oa_callback_log 回调
```

### 4.4 采购出票链路

```
自动出票规则(可配置):
  PMC配置: 全局出票策略、价格验价阈值
  TMC配置: 可用采购渠道、是否允许外采、自动采购规则
  MMC配置: 使用的采购渠道列表、自动采购开关

出票流程:
  订单支付 → 入队(queue_task) → 验价(阈值比对) → 自动出票
  失败降级: 价格超阈值 → 挂起等待人工 → 无票 → 联系客户改签/退票
```

## 五、技术架构要点

### 5.1 全链路追踪

```
trace_id 生成规则: {timestamp_ms}_{tenant_id}_{random_6}
span_id: 调用链层级标识
parent_span_id: 父级调用

传播路径: HTTP Header → Swoole Coroutine Context → MQ Message Header → 日志文件 → 数据库trace_id字段 → 阿里云SLS
```

详见: `09_全链路追踪实施方案.md`

### 5.2 异步队列（关键场景）

| 场景 | 队列名 | 优先级 | 说明 |
|------|--------|--------|------|
| 出票请求 | ticket:issue | P0 | 航司接口异步响应 |
| 退款打款 | refund:execute | P1 | 审核通过后异步打款 |
| 大客名单导入 | corporate:import | P2 | 批量处理 |
| 月结账单生成 | finance:statement | P2 | 定时触发 |
| 航变通知推送 | notify:flight_change | P1 | 延迟/取消通知 |
| 订单状态变更通知 | notify:order_status | P2 | 消息/短信/推送 |
| 采购核销匹配 | procurement:verify | P2 | 导入匹配 |
| 积分过期处理 | member:points_expire | P3 | 定时任务 |

队列任务版本控制: queue_task表含 `task_version` + `task_snapshot` 字段

### 5.3 微服务拆分预留

| 预留项 | 当前实现 | 未来拆分 |
|--------|---------|---------|
| 全链路trace_id | 所有日志表+关键业务表 | 分布式追踪(Jaeger/Zipkin) |
| 领域事件 | 内部同步调用，预留Event Bus | 异步消息总线 |
| 数据库按领域 | 表前缀严格按领域(order_/finance_/member_等) | 物理拆库 |
| 接口层 | Controller严格按领域划分 | 独立服务 |
| 配置外部化 | 业务规则存数据库rules表 | 独立配置中心 |

### 5.4 扩展业务预留

| 扩展业务 | 预留方式 | 接入设计 |
|---------|---------|---------|
| 用车服务 | order_item_car表已补5个扩展字段 | 通用订单项接口，新增car服务实现 |
| 景区门票 | 预留order_item扩展机制 | 新建scenic_*基础表 + order_item_scenic |
| 私人旅行高定 | 预留order_itinerary行程概念 | 新建itinerary_*表，关联已有order_item |
