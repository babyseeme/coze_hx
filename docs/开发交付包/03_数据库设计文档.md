## 三、关键索引规范

### 3.1 必建索引

```sql
-- 全链路追踪索引(所有含trace_id的表)
ALTER TABLE `order` ADD INDEX idx_trace_id (trace_id);
ALTER TABLE `order_item_flight` ADD INDEX idx_trace_id (trace_id);
ALTER TABLE `payment_log` ADD INDEX idx_trace_id (trace_id);
ALTER TABLE `finance_refund` ADD INDEX idx_trace_id (trace_id);
-- ... 所有P0/P1表同上

-- 租户隔离索引(所有含tenant_id的表)
ALTER TABLE `procurement_channel` ADD INDEX idx_tenant_id (tenant_id);
ALTER TABLE `after_sale` ADD INDEX idx_tenant_id (tenant_id);
-- ... 所有业务表同上

-- 订单查询复合索引
ALTER TABLE `order` ADD INDEX idx_mmc_status_created (mmc_id, status, created_at);
ALTER TABLE `order` ADD INDEX idx_user_status (user_id, status);

-- 大客户白名单查询
ALTER TABLE `corporate_whitelist` ADD INDEX idx_id_number_airline (id_number, airline_code);
```

### 3.2 禁止索引

- 不要对 JSON 类型字段建索引
- 不要对 text/longtext 建普通索引
- 不要对 status 单独建索引(选择性太低)

## 四、数据迁移注意事项

1. **order_tag字段**: V10为VARCHAR(64)，V11需改为JSON，需数据迁移
2. **approval_instance**: V10含flow_id字段，V11改为OA对接需移除flow_id
3. **新增tenant_id**: 子表需回填tenant_id（从主表JOIN更新）
4. **新增trace_id**: 历史数据trace_id为NULL，不影响查询

详见: `sql/V11复核整改.sql`
